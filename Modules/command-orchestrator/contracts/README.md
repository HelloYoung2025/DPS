# Command Orchestrator contracts

The module consumes `operation.compiled/v1` and Policy-owned `execution.authorization/v1`, and uniquely owns `command.dispatch/v1`, `command.receipt/v1` and `command.receipt.signed/v1`. Command Orchestrator constructs and remains the authorization wire producer and owns the dispatch digest. Its existing `IPolicyExecutionAuthorizationSignerV1.SignAsync(ExecutionAuthorizationV1)` consumer port is unchanged; a production Policy provider is still pending. The returned payload must preserve the producer and every canonical byte. Command.Contracts references Policy.Contracts; Policy has no reverse Command or Compiler reference.

The initial, not-yet-released v1 command protocol is exactly one ordered step. It carries the required authoritative `approval_sha256` from `operation.compiled/v1`; dispatch validation, command canonical bytes, and execution authorization all bind that value. The JSON Schema matches the C# producer and consumer invariant; multi-step operations require a separately versioned compatible protocol rather than sorting steps by ID.

`execution.authorization/v1` fixes the command-digest domain and encoding plus the ECDSA P-256/SHA-256, IEEE P1363, Base64 signature format. It binds the exact BOM digest, monotonic active generation, and SHA-256 of the supervisor-issued opaque execution token; the raw token is never part of this contract. Human guidance is in [Policy canonical guidance](../../policy-approval/contracts/provided/execution.authorization.v1.canonical.md); the Schema-bound machine specification and cross-language bytes/digest/signature vector are in [Policy machine specification](../../policy-approval/contracts/provided/execution.authorization.v1.canonical.json). Signed values are authorization evidence only; Executor Gateway must compare them with independently verified activation truth.

The sole `ExecutionAuthorizationV1` definition is in Policy.Contracts. Its historical `Dps.CommandOrchestrator.Contracts` CLR namespace preserves current source usage; it does not denote ownership or promise old binary compatibility. `ExecutionAuthorizationProtocolV1` keeps command canonicalization here and forwards authorization methods to Policy’s `ExecutionAuthorizationCanonicalV1`. Deployments must select the coordinated package group.
