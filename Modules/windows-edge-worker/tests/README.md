# Test boundaries

- `unit`: leases, request hashes, idempotency, allowlists, and native/postcondition truth. The hardened local floor is `13`.
- `contract`: the hardened local and central candidate floors are both `10` for strict wire validation, versioned duplicate/retry truth, owner-defined golden vectors, and a reflection guard proving Unix diagnostics remain non-counting.
- `provider-contracts`: a required Python consumer-differential suite reads the Supervisor, Journal, and Executor owner Schemas, locks the exact 55-case Supervisor/Journal provider-owned corpus ID sets (including the signed Supervisor directive and Worker-only durable-drain receipt), binds both drain auth profiles and the owner checksum machine profile, and treats the Executor-owned `native.stop.proof/v1` vectors only as bounded quarantine classifiers. The worker keeps no private copy of those Schemas or profiles; an owner case or profile change forces explicit consumer rebinding.
- `Integration`: the hardened local and central candidate floors are both `47`. It counts only cross-platform simulations: crash phases, persistent retry budgets, Journal append failure, crash-after-append reconciliation, persistent drain truth, exact Worker receipt PREPARED/COMMITTED recovery, PSS retry idempotency, signed-directive continuation, clock rollback, real local-process termination/restart, exclusive writer fencing, host-blocked or store-rejected live path replacement, bounded crash-tail recovery, tamper, hard resource limits, and legacy v1 quarantine. The latter proves repeated, concurrent, cancelled, and conflicting v1 requests cause zero authority calls and zero proof files; restart exposes only bounded owner-decoded metadata. These tests keep `EvidenceKind=SIMULATION`; process-boundary cases also carry `ExecutionBoundary=LOCAL_PROCESS`.
- `UnixDiagnostic`: six explicitly non-counting diagnostics exercise Unix 0700/0600 modes, effective-user ownership, symlink, hardlink, FIFO, and foreign Journal-file mode preservation. They carry `EvidenceKind=UNIX_ONLY_DIAGNOSTIC` and `CountsToward=NONE`, are excluded from the required Unit/Contract/Integration commands, and must throw rather than return-as-PASS on a non-Unix host. They cannot satisfy or contribute to Windows ACL, reparse-point, file-ID, or power-loss evidence.

The terminal-audit simulations assert that a terminal receipt is not returned while its deterministic Journal append is missing, that a repeated request reuses the same `entry_id` and payload hash after an append failure, and that startup reconciliation finishes a crash-after-append record without redispatch or command redelivery. The Journal test adapter independently canonicalizes and hashes the payload instead of echoing the worker's claimed hash, and a cross-module simulation sends the worker DTO through the real owner `JournalStore`; corrupted and raw-noncanonical hashes fail. A separate executable process harness runs the real `CommandProcessor.ProcessAsync` decision path and terminates at four durable boundaries: transport invoked before a side effect, native side effect before acknowledgement, dispatch acknowledgement persisted, and terminal Journal append before final state. The reconcile-only host is then restarted to prove exact completion replay or persistent uncertain blocking without incrementing the native side-effect counter. Production-composition tests also assert that simulation adapters are rejected in `WorkerRuntimeMode.Production`.

Drain-receipt simulations use distinct ephemeral Supervisor and Worker keys. They prove invalid, stale, wrong-scope, wrong-key, and bad-signature directives cannot stop intake; a long drain gets a fresh completion window; non-UTC time and rollback fail closed; exact raw Worker wire is persisted before append; a crash after the real owner Journal durable append reuses the same wire and signature; same signed statement with a newly randomized Supervisor PSS signature is idempotent; changed routing epoch quarantines; and the returned Worker wire has no Journal-owned rich proof fields. The Journal implementation is wrapped test-only behind append plus readiness, so these remain simulation rather than production IPC or Windows evidence.

Legacy-native-stop tests prove by reflection that the product assembly contains no v1 request/result DTO, no runtime-identity/native-stop/signing interface, and no authority-bearing constructor. The only probe returns non-generic `Task` and always fails closed. They do not issue or durably reuse a proof. Reflection also proves the store's private validated return type has no raw byte-array property; oversized records, oversized decoded wires, decoded non-UTF-8, noncanonical Base64, and post-open artifact exhaustion fail before metadata release on every supported test host. The required Integration suite also proves a live native-store writer-path replacement is either blocked by the host or detected by the open-handle identity fence. Unix link/FIFO/mode/owner checks remain separate non-counting diagnostics. A local-process launch test also exercises the real Worker entry point with the Supervisor's current zero-argument launch shape and requires exit `64`, usage-only stderr, no stdout status, no runtime-state creation, and therefore no Worker intake or route transition. This is negative compatibility evidence only; it does not simulate a successful stage, health check, cutover, or Windows host. The Policy v2/challenge, Release-BOM authority, Supervisor route assignment, authenticated live Worker IPC, shared fixed launch ABI, Windows ABI, Windows ACL/file-ID gate, and production key service remain `WAITING_EXTERNAL`.

These tests do not invoke ZennoDroid or a phone. Required suites are labelled unit, contract, or `SIMULATION`; Unix diagnostics are non-counting. None can issue Windows or device verification. Windows ACL evidence is `NOT_RUN`, not a passing branch inside a cross-platform test.

The current locked .NET restore is `INFRA_ERROR` because of local CSSM/NuGet audit-source failures. A source build and direct in-process MTP executable run are diagnostic only; they do not replace the required locked wrapper or raise the evidence level.

## P10 lease and terminal replay regressions

The original lease slice added 36 black-box cases through the existing `CommandProcessor.ProcessAsync` entry: 23 Unit and 13 Integration cases. The original implementation produced 18 new Unit assertion failures and 13 new Integration assertion failures, while the original 13 Unit and 47 Integration cases still passed. The same assertions are retained in the candidate; its resulting totals were 36 Unit and 60 Integration. Original wrapper floors, filters and fail-on-skip behavior remain unchanged.

- Equality and one tick after expiry are tested before initial reservation, after ACCEPTED Journal persistence, after MarkAccepted persistence, after MarkTransportAttempted persistence, and on both explicitly unacknowledged result and exception retry paths.
- Non-UTC clock values and observed clock rollback fail closed. A process-local clock fault remains latched for subsequent new execution requests.
- Actual ProcessAsync success, failure, shadow, acknowledged unknown and uncertain submission results are replayed after expiry. Memory-store mutation counters and reopened durable state/Journal bytes prove no new writes or native calls during completed replay. The durable snapshot starts after process construction, which still persists its normal process epoch.
- Wrong hashes, changed scope, malformed scope and unknown major versions cannot expose a stored receipt. A concurrently active duplicate does not call the reserving store entry, and the original ACCEPTED wait cannot authorize a later expired native call.
- A real owner Journal append followed by interrupted finalization is reconciled after expiry with the exact stored entry and payload. A reopened possibly-submitted attempt retains UNKNOWN_OUTCOME without redispatch. Native results that arrive after expiry retain their acknowledgement and postcondition truth.

The existing real child-process crash/restart suite is retained. The new reopened-store tests use `EvidenceKind=SIMULATION`; they do not relabel a same-process fixture as a child-process crash. New helpers are `LeaseRegressionClock`, `LeaseRegressionTransport`, `LeaseRegressionJournal` and `LeaseRegressionStore`. The latter forwards the new read-only store query without incrementing its mutation counter.

`ICommandStateStore.ReadExisting` is an explicit public C# interface addition. All six in-repository implementations are covered: InMemoryCommandStateStore, DurableCommandStateStore, FailOnceFinalizeStore, BlockingClaimStateStore, CrashWindowStateStore, and the new LeaseRegressionStore. Unknown external implementations require adaptation; binary compatibility is not asserted. No owner wire contract or Journal format changes.

Linux outcomes are local simulation results. Worker Unit/Contract, Journal Unit/Contract and Supervisor Unit/Contract/A-B retain their declared macOS/Windows environment gaps even if the Linux runs pass. Full candidate results and independent QA are bound in provider-local product receipts, not inferred from these test counts.
