# Operations

Run `bash Modules/windows-edge-worker/operations/test.sh Unit`, `Contract`, or `Integration`. The hardened 34-line audited wrapper enforces exact local floors of Unit `13`, Contract `10`, and Integration `47`; skipped or missing tests fail. `Integration` counts only cross-platform simulation and process-boundary cases. Six `UnixDiagnostic` cases are deliberately outside those required commands and carry `CountsToward=NONE`; a required Contract reflection guard prevents them from being relabelled into a counted suite. Run them only as local Unix diagnostics. Windows ACL, reparse/file-ID, and power-loss validation remains a separate external `NOT_RUN`/`WAITING_EXTERNAL` gate, never a return-as-PASS branch.

The supervisor is intended to start each worker from an immutable, digest-verified A/B version directory. A worker accepts only a valid unexpired lease and exact v1 `COMMAND` decoded by the strict wire boundary. It journals acceptance before dispatch and advances command state through `Reserved`, `Accepted`, `TransportAttempted`, `DispatchAcknowledged`, `CompletionPrepared`, and `Completed`. `CompletionPrepared` durably binds the terminal receipt to one deterministic Journal entry. `Completed` is legal only after a matching durable Journal receipt; a crash before or after append replays the same `entry_id` and payload hash instead of exposing an unaudited terminal success.

Production composition is now executable only in reconcile mode on the current non-Windows diagnostic host: `Dps.WindowsEdgeWorker --production-reconcile --state-dir <absolute-private-directory>`. It opens a 0700 runtime directory and 0600 Worker-owned regular files, an exclusive process writer fence, and a checksum-chained append-only command-state store. Journal append and read-only readiness arrive only through an external IPC proxy; the Worker source has no Journal implementation dependency and does not inspect Journal files. It replays every `CompletionPrepared` terminal write before reporting drain truth. The command state has 64 MiB file, 1 MiB record, 512 KiB payload, 100,000-command, and 128 crash-tail hard limits; corrupt chains, partial tails, insecure permissions or ownership, symbolic links, hard links, FIFOs and other non-regular Worker files, open-handle/path identity changes, Journal quarantine, or a second writer fail closed. A partial final record is isolated under a content-addressed private crash-tail file and only an exact bounded existing copy is accepted after a second crash window.

Action intake remains intentionally unavailable. Production `CommandProcessor` instances start with intake stopped, the native transport is disabled pending the separately reviewed Windows ABI, and a non-drained restart exits with status 78. The executable also rejects Windows startup until the Windows identity/ACL rules and native ABI are probed and bound; macOS local-process results cannot approve a Windows state directory. `InMemoryCommandStateStore` and the test Journal remain simulation-only. `module.yaml` remains `proposed` with `releaseEligible: false`.

Drain cutover has a separate signed path. The removed free-text exchange `DRAIN` fails closed. `WorkerDrainReceiptIssuer` accepts only the Supervisor owner's canonical `edge.worker.drain.directive/v1`, an exact active expectation, and an externally pinned Supervisor RSA key. It validates all of those before `StopIntake`, reconciles until in-memory and persisted drain truth are zero, obtains a fresh UTC completion window from the injected clock, and signs one Worker-only `edge.worker.drain.receipt/v1` through an injected authority that exposes sign/verify but not raw private-key ownership. Non-UTC time and clock rollback fail closed.

The signed Worker wire is written once to the separate checksum-chained `drain-receipts.jsonl` PREPARED store before Journal append. The store has a 128 MiB file limit, 128 KiB record limit, 32 KiB proof limit, 4,096 transition limit, an exclusive writer fence, path/handle identity checks, strict private permissions, and content-addressed crash-tail isolation. `WORKER_DRAINED` binds the exact `worker_receipt_wire_sha256`; only a fully matching durable Journal receipt advances COMMITTED and permits return to Supervisor. A crash or bounded append timeout keeps PREPARED, and restart re-verifies the owner-signed directive and reuses the exact raw Worker wire instead of generating another randomized RSA-PSS signature. Supervisor separately requests and verifies Journal's rich attestation by deterministic entry ID. The Worker never receives that wire, an attestation/admin capability, or any Journal key.

The withdrawn Executor-owned `native.stop.proof/v1` path is quarantine-only. `WorkerNativeStopProofIssuer` is now an internal zero-authority tombstone with no v1 request/result DTO, no runtime-identity/native-stop/signing interface, and no authority-bearing constructor; its non-generic task always fails closed. The internal bounded store can inspect an already-existing owner-canonical v1 artifact and return only digest/size/disposition metadata; it has no creation or raw-wire API, its private return path retains no byte array, and every allocated temporary decoded buffer is zeroed on success or rejection. Its writer fence, live writer-path identity check, continuously rechecked size/artifact ceilings, and malformed/conflict fail-closed behavior remain so restart diagnostics cannot be turned into proof reuse. The artifact budget runs in the required cross-platform suite; Unix link/FIFO/mode/effective-owner probes are non-counting diagnostics and do not stand in for Windows ACL evidence.

This component is still not a production cutover endpoint: the Supervisor has no frozen route-assignment contract or live Worker IPC; the Policy v2/challenge and Release-BOM authority packs have no frozen Worker-facing API; Windows ACL/identity rules, the native ABI, Job Object lifecycle evidence, and actual A/B routing are absent. The current launch ABIs also deliberately fail closed: the Supervisor starts the exact Worker executable with zero caller arguments, while this Worker accepts only `--production-reconcile --state-dir <absolute-private-directory>`, and that reconcile host still rejects Windows until the native ABI and ACL evidence are bound. The local-process test proves that the Supervisor's current zero-argument launch exits before opening Worker state or enabling intake; it is not stage, health, cutover, or route-transition evidence. The required resolution is one separately reviewed, fixed, Release-BOM-protected launch ABI shared by both owners, not weakening either side locally. The quarantine tests prove only zero-call/zero-wire and bounded restart behavior. Therefore `releaseEligible` remains false and Windows, ZennoDroid, and ADB remain `NOT_RUN`; neither `WINDOWS_VERIFIED` nor `DEVICE_VERIFIED` is claimed.

Restart before `TransportAttempted` safely resumes. The state store persists the attempt count as well as the phase, and rejects any third native dispatch even when the first or second attempt ended at a crash boundary. The current reconcile-only host preserves `TransportAttempted` and `DispatchAcknowledged` as durable uncertain states, keeps intake disabled, and exits 78; it does not synthesize a terminal `UNKNOWN_OUTCOME`. A future separately reviewed command-reconciliation intake may turn an exact redelivered command into the matching durable `UNKNOWN_OUTCOME`, but it must never blindly redispatch it. Same-epoch duplicates are retryable `IN_PROGRESS` only in `Reserved` or `Accepted` with a fresh lease and trusted clock; later phases return non-retryable reconciliation truth. Drain is false until intake is stopped, in-memory work is zero, and the injected state store reports zero unfinished, uncertain, or completion-pending commands. Rollback changes supervisor routing; it never deletes the journal or rewrites native results.

The worker's strict exchange codec consumes production `COMMAND` and produces `RECEIPT` and `HEALTH`; unknown kinds including free-text `DRAIN` fail closed. The executable host currently exposes only startup reconciliation. A command receipt cannot claim verified success unless dispatch acknowledgement, native success, and postcondition verification are all true.

## Per-attempt lease checks and expired receipt replay

The command path validates structural contract identity, scope and the exact request hash before reading any stored receipt. `ICommandStateStore.ReadExisting` takes a read-only snapshot under the store lock: it neither reserves a missing key nor claims another process epoch. Completed same-hash requests return their original receipt with duplicate semantics even after lease expiry, without a new state or Journal write. Creating a new processor still persists the normal process-epoch record.

Fresh execution checks occur before reserving or reclaiming an unsubmitted command, at every native attempt, and again immediately after the durable MarkTransportAttempted call returns. Equality with lease expiry is expired. No asynchronous wait or persistence call sits between the final successful time check and the native invocation. ACCEPTED persistence and confirmed-not-submitted retry waits therefore cannot extend the lease. The process rejects nonzero UTC offsets and observed clock rollback and latches a clock fault until restart. This is a process-local observation guard, not a replacement for the host's trusted clock or cross-process time authority.

If the final pre-native check fails after an attempt was recorded, no native call has occurred. The existing MarkPreDispatchRetry transition records that known unsubmitted phase, while retaining the consumed attempt count. The command returns non-retryable REJECTED and remains unfinished; expiry does not fabricate a terminal journal entry, erase prior state, refund the two-attempt budget, or make drain true. Persistence failures still propagate with the durable store's existing fail-closed behavior.

CompletionPrepared and possibly-submitted recovery are reconciliations of existing facts. They may claim the existing state and finalize its exact stored terminal write after expiry; this is not completed read-only replay and does not grant another native attempt. Once native submission is possible, late acknowledgement, failure and UNKNOWN_OUTCOME retain their original truth instead of being replaced by lease rejection.

The public C# ReadExisting member requires existing store implementers to adapt. The two product stores and all four repository test adapters implement it; no unknown external binary compatibility is claimed. TryBegin retains reservation/claim semantics. Wire schemas, Journal format, owner contracts, original wrappers and pins remain unchanged. Production intake stays closed pending the existing IPC/Windows/authority gates; this local slice does not complete P10 or P21 production wiring.
