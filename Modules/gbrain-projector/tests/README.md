# gbrain-projector tests

This directory separates unit, contract, integration, resilience, Windows, and device evidence. The exact required suites and commands are declared in ../module.yaml.

The required machine-count floors are 13 unit, 9 contract, and 16 real-PostgreSQL integration tests. Removing a security scenario without replacing equivalent executable evidence must fail the gate.

A required check releases only on PASS. FAIL, SKIP, PARTIAL, NOT_RUN, INFRA_ERROR, NOT_APPLICABLE, an empty test set, or missing raw evidence is a failure. Mock evidence must be labelled and cannot satisfy integration, Windows, ZennoDroid, ADB, device, canary, or scale gates.

Rendering is side-effect free; the module now persists Source bindings and rendered revision truth. PostgreSQL integration must use a real PostgreSQL 18.4 instance reporting exact `server_version_num=180004` and two distinct direct-login credentials in `DPS_TEST_POSTGRES_ADMIN_URI` and `DPS_TEST_POSTGRES_RUNTIME_URI`. A required real negative uses `DPS_TEST_POSTGRES_WRONG_VERSION_URI`, which must connect to a real PostgreSQL server reporting any value other than `180004`; a missing or incorrectly targeted negative is `INFRA_ERROR/NOT_RUN`. An in-memory replacement, one shared credential, a different database/cluster, missing environment, or `SET ROLE` cannot satisfy the required integration suite. The test-only admin creates and drops isolated schemas, databases, and role-membership fixtures; grants/revokes the test parameter privilege; changes and resets the test runtime role default; and disables internal FK triggers for fault injection. This is test infrastructure authority, not a runtime permission.

Unit and contract suites cover the retained v1 collision pair, exact version matching, nonce `0..1023`, fixed derivation, preoccupied real-candidate retry, re-signed forged binding rejection, same-Soul concurrency, restart reads, capability scope, nonce exhaustion quarantine, PostgreSQL microsecond boundaries, v1 byte freeze, v2 canonical proof, and migration shape. They do not prove PostgreSQL or GBrain network write/read-back.

The real integration suite covers distinct identity and same-database lock-namespace proof before DDL, role membership in both directions, signed expected-owner binding, hostile startup `search_path`, `session_replication_role` defaults/parameter privilege, weak precreated table rejection without repair, unexpected views/types/rules, near-exact but wrong CHECK/FK/trigger definitions, quoted-literal canonicalization attacks, disabled internal FK triggers, cross-schema FK substitution, exact-schema no-op rerun, administrator-runtime rejection, effective SELECT/INSERT-only ACL, all three tables across owner-side UPDATE/DELETE/TRUNCATE triggers, restart/concurrency, sub-microsecond zero-write rejection, equal-count head ambiguity, and fault-injected relational/canonical/JSONB splits. Fault injection first initializes a valid runtime, then uses the migration owner to deliberately remove the relevant guard; this proves the read verifier independently fails closed rather than merely retesting a database CHECK.
