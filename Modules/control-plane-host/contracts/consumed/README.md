# Consumed contracts

The signed provider contracts are parsed from their exact owner schemas and current compatibility floors. `action.execution.promotion/v1`, `approval.submission.reconciliation/v1`, `approval.submission.recovery/v1`, and `approval.submission.state/v1` are owned by `policy-approval`; this module references that strict public contract pack and does not duplicate its schemas, DTOs, codecs, binding algorithms, or corpora.

Control Plane Host is the declared wire producer of reconciliation and recovery even though Policy owns their API contracts. It uses pairwise-distinct, strongly typed external signing capabilities, verifies each returned P1363 signature against the capability's canonical NIST P-256 public key, and dispatches through separate role-specific proposed port facades. The facades validate self-declared auth scopes, distinct credential-authority fingerprints, and bounded timeouts, but do not prove authenticated transport or process/credential isolation; production adapters that derive identity from actual mTLS, protected IPC, or equivalent Policy/database-role sessions remain unimplemented. The signed Policy state response is decoded by the owner codec, has its public commitment recomputed, is verified against the configured Policy-state authority, and must exactly match attempt, approval, proposal, command, lease, Soul, device, account, trace, idempotency, Release BOM, native binding, intent, predecessor, state, and evidence expectations.

The host consumes only the exact v1 results declared in `module.yaml`. It parses bounded strict UTF-8 bytes without importing provider implementation types, rejects duplicate/additional fields, binds canonical identity scope and lifecycle state, and verifies the producing module's P-256 signature against the current signed BOM/key trust revision before persistence. Platform-account alias-key and authorization-evidence metadata must use the provider-owned lowercase canonical grammar; mixed-case authority metadata fails closed. Contract tests bind the consumer parser directly to the provider-owned shared corpora at their canonical module paths; no provider fixture is copied or privately reinterpreted here. GBrain readback is a signed adapter proof whose declared checksums must match; this host does not possess the original GBrain bytes and therefore does not claim a local content-checksum recomputation.

## Quarantined Soul-current session edge

Host consumes Soul-owned `soul.current.lease.session/v1` over reciprocal AF_UNIX `read-only-query` edges. Query/resolution v1 remain immutable inner assets; they are not separate in-process runtime edges. Host references only the public contract pack and does not load Soul runtime or hold Soul PG credentials/private keys. The removed in-process factory had no governance exception.

The public envelope also carries Host↔host-auth possession messages; it is not hidden as provider-internal traffic. See the [owner phase/field matrix](../../../soul-registry/contracts/README.md#public-envelope-and-phase-matrix). Host verifies exact query/session/config/BOM binding, owner signatures and a fresh Host-generated status request/nonce; a boolean is insufficient. It explicitly waits for release ACK and then rechecks the original five-second entry budget, cancellation and signed windows. Only `SOUL_ACTIVE_AS_OF` is returned under the closed synthetic seam; no Binding/Device/Account or downstream commit guarantee follows.

Public Open always rejects, including enabled installations. No startup/CLI/listener route or production trust is installed. Quarantine/release-ineligible settings and global failure history remain intact; successful isolated tests are not activation or formal issuance.

## Policy shadow chain (P06, SHADOW only)

Host consumes Planner-owned `action.proposal/v2` inbound from `planner` and relays the exact bytes to `policy-approval` with `preserveProducer: true`; Planner stays the schema producer. Host is the wire producer of Policy-owned `approval.evaluation.request/v1` (scope `policy:evaluate`): it binds the proposal ID and `dps.planner.action-proposal-sha256/v2` commitment, scope, trace, idempotency, Release BOM, `occurred_at` equal to the proposal's and `valid_until = occurred_at + 120 s`, always in `SHADOW` mode, and signs the owner canonical bytes (P-256 P1363). It consumes Policy-owned `approval.readback/v1` through the owner codec and accepts it only when major is 2, the commitment, proposal ID, scope, trace, idempotency and BOM match, the decision is shadow-only `DENIED`, and the persisted request signature verifies over this request's canonical bytes (an exact replay returns the originally persisted signature). v1, unknown majors and malformed proposals fail closed before signing.

Host src references only the Planner and Policy contract packs. The Planner and Policy implementations are wired only in the test-only entry process `tests/PolicyShadowChainProcess`; `HostStartup` accepts only `--self-check` and no product path constructs the chain. The Soul, Binding and account ids the chain carries are only a SHADOW echo and never an authorized identity. Host neither consumes `soul.resolved` nor declares any `soul.*` edge for this chain.
